Written guide

Connect a second computer

Follow these first connection steps on Linux and macOS beta 29262 or later. The video above follows the Linux flow from fresh installations; the Mac walkthrough is linked in #2489.

Before you begin
Install Okilum on both computers and open your existing vault on the first. Keep both on the same LAN for first pairing. Okilum sets up its bundled Syncthing automatically when no existing connection needs attention. No account or server is required. On Mac, allow local network access when macOS asks. If Login Items approval is required, allow Okilum Sync in System Settings → General → Login Items, then use Try again. Keep the existing Sync state and identity. The Mac walkthrough and first containing beta are recorded in #2489. Windows requires the installed signed build with its Sync helper; portable packages do not include background Sync. Native first-merge acceptance and containing beta builds are recorded in #2043. Keep a separate backup: Sync can propagate deletions.

  1. First computer

    Share your vault

    Open the app menu → Share with another computer…. Under Local vaults or Vaults, select Share with my computers. Enter a recognizable name under This computer.

    If an existing Syncthing is found, explicitly select Use connection. For an already synced vault, select Choose existing synced vault, check its folder and device, then select Use this connection. Okilum reuses it without taking over its lifecycle or network settings.

  2. First computer

    Create an invitation

    Select Add computer, enter the computer name, then Create pairing link and Copy link. Transfer the invitation privately to your second computer. Keep Okilum open here. The invitation pairs one computer and expires after one hour. If it expires, create another. Do not post the complete URL publicly.

  3. Second computer

    Request the connection

    On the welcome screen select Get notes from another computer. In Sync, select I already have a pairing link, or Add computer → I have a link from another computer. Enter this computer’s name under This computer. Use Paste pairing URL, then select Request connection. You can also reach this step in Settings → Sync. Select Use connection if prompted about an existing runtime.

  4. First computer

    Confirm the computer

    Check the requesting computer’s name and identities. Select Approve only for the expected request. The new computer can then see its authorized vaults. Further vault selections between this pair need no new URL.

  5. Second computer

    Choose the vault and local folder

    Under Available vaults, select Choose folder for the intended vault. In the native folder dialog, choose or create a local folder. After selecting the wanted vaults, select Start first sync. If the folder contains files, review New here / New there / Same / Conflicting, then explicitly confirm the merge. Every original is retained; different versions stay on both computers. Little overlap requires an additional acknowledgement. Changed files require a fresh preview; interrupted work stays visible under Recover first sync. Closing the preview starts no merge (#2043). Never clear a working folder to force setup.

  6. Second computer

    Receive your notes

    First transfer starts automatically. Wait for First sync complete; the received vault opens when ready. No extra Enable or daemon setup step is needed. A paired entry alone does not prove receipt. Saved edits and deletions then sync both ways.

Once connected

Keep writing

Open a note

Open welcome in the vault tree. Use the pencil control to enter the editor.

Save your change

Add a line and press Cmd+S on Mac or Ctrl+S on Linux.

Check the other computer

Open the same note and confirm the new line appears. You can also edit and save there to sync back.

Network, conflicts and common questions

Managed Linux Sync keeps explicit Syncthing peer addresses and uses public discovery and encrypted relays by default. In Settings → Sync, Only local network and VPN disables public discovery, relays and router traversal for every vault using this connection on this computer. Direct addresses must remain reachable on your LAN or VPN. First pairing still needs the same LAN. External Syncthing network options are changed in Syncthing itself.

If an incoming change reaches a note with unsaved edits, Okilum keeps your text and shows a notice. Explicit Save or Keep both versions preserves local text in a separate .okilum-conflict-<time>-<random> file, keeping its extension and leaving the incoming file unchanged. Clean editing and reading views update when changes arrive. Conflict review offers Keep this, Keep that and Keep both (#2044). Managed folders keep previous remote versions for 30 days by default. Restore overwritten notes from Note history and deleted notes from Recover notes (#2045). Sync is not a backup of every local edit.

No server is required. An always-on Linux Okilum computer can receive another trusted copy through the same steps. A headless Linux server can run okilum sync serve and pair through that running service with okilum sync invite. For a plain Syncthing peer, share the vault explicitly, then edit the trusted sharing device → Advanced → Introducer. Leave Skip Introduction Removals disabled. New computers sharing that vault are introduced without repeated server configuration. Devices added manually still need manual removal. Settings → Sync → Remove propagates through authenticated paired/introducer routes. Check the device ID before confirming; disconnected computers follow when reconnected (#2042). Removing Syncthing shares/connections cannot recall files already copied. Closing Okilum or disabling its Sync UI is not remote revocation.

The former service/hub/passkey desktop enrollment is gone (#2049). Use the pairing URL and confirmation above.
