# Keep Discussion decisions as reusable goal input

Approved implementation contract for [#253](https://git.oklabs.uk/BeFeast/okilum/issues/253). Implementation and validation status follow the issue; this document is not an acceptance receipt. Source seams inspected at 40faa92fe4c7db631bf30e35d534bc1742808612 and reconfirmed after the shell-only #250 correction at 6ecf5720eb144d08894f2f24102e3f1b7de16720. Recovery direction incorporates the independent bounded SourceStore recovery audit and root's pending-receipt/readback distinction. The bounded implementation follows this contract; source/unit evidence does not substitute for native or compatibility acceptance.

## User interaction

Choose one saved user message in goal A → Keep as goal decision → review its exact complete text, original actor, conversation and turn → explicitly Save → the same goal brief and later new Discussion can reuse it once. Goal B cannot consume it automatically. Text is read-only in this review: no automatic extraction, paraphrase, subset, semantic supersession or assistant-message promotion. Cancel writes nothing. The label means retained user input, never factual verification. Save triggers no provider/task/engine/proposal/Attention operation and changes no existing context packet or stage envelope.

Only a persisted, nonempty user message with a valid matching retained Discussion turn is eligible. Legacy transcript rows lacking trustworthy turn/actor binding get a clear unsupported explanation. Preserve the existing assistant Save as note and New note flows. Review must not replace an existing source draft; use existing navigation/close protection. Do not claim transient review crash recovery before a durable Save exists.

## Canonical shape and admission

Propose a distinct `record_type: discussion-decision`, at `records/discussion-decision-<id>.md` (using the workspace records directory). Keep `ai-brain/v1`; add a `discussion_origin` object with schema `tessera-discussion-decision-origin/v1` rather than fields to deny-unknown-fields Discussion turn/envelope schemas. Required common metadata: canonical id, brain_id, goal_id, actor_id, received_at (UTC), verification=unverified. Body is the exact selected message bytes immediately after the closing frontmatter delimiter, without an H1, generated prose or added terminal newline. Serialization/parsing must preserve leading/trailing whitespace and CRLF in that body. The fixed display title comes from the admitted kind. Origin records conversation_id/path, source_revision, turn_id, user_message_index, user_message_sha256, transcript_prefix_sha256, context receipt hash and original turn timestamp. Attribution comes from the validated stored turn, not the current UI row or assistant. P1 saves only the current local actor's own turns; do not silently substitute the saver for an earlier author.

A stable decision UUID identifies one retained choice per turn; source revision is provenance, not a new identity on each reread. Derivation: concatenate each UTF-8 value prefixed by its four-byte unsigned big-endian byte length, in order (namespace, canonical lowercase brain UUID, goal UUID, conversation UUID, turn UUID, exact actor string); SHA256; take the first 16 bytes; set UUID version 8 and RFC variant bits; render canonical lowercase UUID. Namespace `tessera/discussion-decision/id/v1` yields the decision ID; `tessera/discussion-decision/operation/v1` yields a distinct operation ID. No new hash/UUID dependency is needed. Golden vector: brain/goal/conversation/turn are respectively `00000000-0000-4000-8000-000000000001` through `00000000-0000-4000-8000-000000000004`, actor `local:oleg`; decision ID `6ff223da-25be-858c-ba2c-f3b3c6c2e4e3`, operation ID `3ad4968d-2780-8afb-8ec9-e1da3aa16263`. A second click opens the existing retained save; it never overwrites or emits another record. A moved/changed conflicting deterministic target is visible, not assigned a new UUID.

At first Save the backend validates actual canonical conversation identity/revision, exact user text, unique turn mapping, text/prefix hashes, valid retained context receipt, actor binding and original goal under the existing owner mutex after pending projections are resolved. No new record may cite an invented or stale origin snapshot. The source snapshot is origin evidence, NOT a fabricated base for the new target: SourceWrite expected_revision and base are both null.

After Save, origin revision is historical provenance: later conversation appends or deletion do not silently invalidate the saved decision. Brief admission validates the canonical decision itself, exact path/derived ID, ownership, origin shape, UTF-8/body hash, timestamps and unverified authority. A known SourceStore create receipt anchors original owner/provenance when available; canonical-only portable records may be admitted if self-consistent, with no claim of cryptographic authorship or factual truth. Raw source edits remain possible; malformed or owner-relabelled records are omitted visibly. Do not require a new journal or retain whole conversation/provider envelopes inside an 8 KiB citation.

## Save and recovery

Add capability `discussion_decision_save: true` and two workspace-only commands using the existing exact expected_workspace guard:

- `discussion_decision_get` takes original goal_id/conversation_id/turn_id and expected_actor_id. It derives both IDs and performs bounded operation/target lookup first. For genuinely absent operation and target only, it reads and validates the current canonical origin, then returns an exact create-only SourceWrite proposal for review (including frozen received_at and full source bytes). This read prepares no durable intent and invokes no provider. For other states it returns the retained request/record with the identity and readback status below.
- `discussion_decision_save` takes the same explicit identity plus the exact reviewed SourceWrite. It validates that proposed bytes, derived IDs and provenance agree, checks historical receipt first, then on a first or unresolved write validates the actual origin revision/turn under the backend owner mutex after resolving prior pending projections. Finally it calls SourceStore with expected_revision=None and base=None. The origin snapshot is read-only evidence, never a target base; it need not be transported or stored in the journal. Reject unknown envelope fields and unavailable capability; no generic source_write/Attention fallback.

Prepare, lookup and Save are bound to the original workspace/goal, not current desktop selection. On first Save, re-read the actual origin and require its exact revision and validated selected turn to match the frozen proposal. This serializes against cooperating service mutations, not arbitrary external filesystem edits across two files; the saved origin revision describes the validated snapshot, not a promise of multi-file atomicity. After sending, UI retains the exact operation/request; restart derives that operation from a selected turn or retained decision provenance. Before a new request is composed, bounded SourceStore lookup must resolve any existing intent, receipt or conflict. No additional recovery ledger or EditorRecovery mode is introduced.

Use `SourceStore::recovery_record_bounded` with a 64 KiB serialized-journal budget, 8,192-byte proposed/current decision reads, and the existing 128 MiB canonical-conversation read/8 MiB envelope/64-turn validation bounds. Oversized/corrupt/unreadable recovery data never becomes NotFound. Do not expose the existing unbounded conflict-current-source helper. Responses return bounded fields and exact target bytes once, not an unbounded raw journal or repeated full source snapshots.

| Lookup state | Required evidence and response |
| --- | --- |
| `not_recorded` | Actual operation NotFound plus actual target NotFound; only here prepare a fresh proposal for exact-text review. |
| `existing_canonical` | No journal, but existing target passes complete canonical admission; open it without writing or claiming an acknowledgement. Invalid/different target is a visible conflict. |
| `pending` | Matching retained request, no receipt/conflict; return that exact proposal and separate target readback. Explicit retry uses the same bytes/operation and still requires matching current origin. |
| `conflict` | Matching request with coherent terminal conflict and no receipt; show bounded original proposed/current target; no fresh base, child operation or new UUID. |
| `already_saved` | Matching request with coherent durable create receipt and no conflict; return historical acknowledgement before flushing projections or consulting current origin. Independently report target `unchanged`, `changed`, `missing` or `unavailable`; never recreate it on replay. |
| `recovery_required` | Contradictory/corrupt/oversized/unreadable journal or divergent unresolved intent; preserve evidence and prohibit a fresh create or replacement. |

Successful-create validation requires request expected_revision=None, journal base/preimage/previous_revision=None, and receipt previous_revision=None, outcome=Written, matching operation/path and exact proposed-byte SHA256. A create conflict legitimately may have a previous revision/preimage of the colliding target: validate their digest/conflict relationship, not the success null rules. Exact request/base equality is mandatory for operation reuse; a malformed receipt must not be treated as a missing one.

A pending receipt with a target whose complete bytes equal the proposal must additionally show `target_matches_proposed` and let the user open that retained canonical decision. It is not a lost decision merely because a later conversation append blocks a still-unreceipted retry. Do not invent an acknowledgement or call it `already_saved`: uncertainty about the receipt and observable canonical existence are separate. SourceStore can finalize a lost receipt through an exact write retry only when fresh origin admission still permits it. The journal retains proposed decision provenance, not the original whole conversation snapshot; changed/missing origin cannot be reconstructed, rewritten or assigned a new timestamp under the same operation.

## Brief and Discussion integration

Extend strict brief admission by an explicit branch; keep actual Attention validation unchanged and replace the current decision/else-result assumption with exhaustive kinds. Keep existing 1,024 candidate inventory, 20 inputs, 8,192 bytes per complete citation and 48 KiB cited-byte limits; both decision types share the budgets and visible omissions. Reject an oversized complete new decision before Save rather than truncate its body. Inventory and sorting remain deterministic; latest result priority stays unchanged. New-record path UUID must equal the ID derived from its embedded brain/goal/conversation/turn/actor, so relabelling a known record's owner without changing its path fails admission. For each new candidate use its derived operation ID for one bounded SourceStore lookup when present; never scan all journals. A missing journal permits portable canonical-only admission; corrupt/mismatching evidence yields visible omission. A valid pending create whose current canonical target exactly matches its proposed bytes remains eligible canonical input; display its receipt uncertainty separately rather than hiding the retained decision.

Use a distinct brief kind/title and original actor; full canonical citation carries provenance through existing packet/export schemas. Update Discussion's existing manual/automatic exact path+revision merge to enrich this kind as well; one copy per input per request. No new frozen turn schema fields. “Once” means deduplication per brief/request, not global one-shot consumption: later conversations can reuse the record. In the original conversation suppress the automatic copy while its exact originating user turn is already present in transcript; retain explicit manual pins and their reasons. Do not deduplicate unrelated turns merely because their text matches.

Old backends lack the save capability and must reject this command without downgrade. Distinct filenames avoid old Attention discovery/admission. Existing ordinary source editors preserve unknown metadata; old readers may display the record as a source and omit it from automatic brief. Do not rewrite historical turn/packet/stage envelopes to teach older clients a new kind. Focused compatibility must verify actual predecessor and fallback binaries, including ordinary conversation append preserving retained context with the new input kind.

## Focused evidence

1. Exact user text/Unicode/whitespace and historical actor/conversation/turn/revision survive Save/reopen; assistant, draft, malformed/legacy, mismatched actor/goal/turn, changed origin and oversize are rejected with no write.
2. Exact retry, crash after intent/after commit/before acknowledgement, repeated selection after restart and changed current target resolve one operation/record; mutated request cannot reuse an operation. Null target base is real, never a fake snapshot. Cancellation and pending-draft navigation are visible.
3. Same-goal brief/new-turn context include the attributed unverified record once; other goal excludes it; manual pin merge and original-transcript suppression work. Matching-text distinct turns remain distinct. Inventory/byte-limit omissions are explicit.
4. Existing Attention/result admission and assistant notes remain unchanged. Original conversation source, reviewed packet and active stage envelope hashes remain unchanged by Save. Instrument provider/task/engine/Attention absence with an independent positive control.
5. Native exact-text review/Save/Cancel/reopen, same-goal brief and New conversation navigation; pure backend preparation tests prove new-turn inclusion without sending to a provider. Do not invent an unsent-context preview UI for this slice. Old-client capability refusal and old-writer preservation on copies, with source/binary pins and honest limitations.

## Manual-only reuse

[Reuse settings](ai-brain-discussion-decision-reuse.md), tracked in #261, adds a separate one-way disposition. The exact same saved file can become `discussion-decision-manual`; automatic brief admission then excludes it. The original create receipt remains historical and its full predecessor bytes remain the admission anchor. Keep never reactivates or rewrites the current manual-only file. Explicit manual selection still requires current source review. No semantic supersession or historical transcript/packet rewrite is introduced.
