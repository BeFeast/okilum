# Hidden Windows update preparation (#2607)

Velopack 1.2.161 starts its delta preparation `Update.exe patch` through
`Command::output()` without Windows creation flags. Piped output does not suppress
a console window. Its final install/relaunch helper already uses
`CREATE_NO_WINDOW`; this patch applies that flag to the background delta helper
as well. Delta downloads, checksum checks, full-package fallback and explicit
installation consent keep their existing behavior.

The after-update hook also refreshes Markdown Open With (three `reg.exe` calls),
Explorer folder verbs (eight) and the `okilum:` protocol (three). All three
registry wrappers now set `CREATE_NO_WINDOW` without changing their arguments
or registry ownership. The existing native Windows registry round trips verify
the folder/protocol operations and neighboring keys. This audit covers both
preparation and post-install callbacks, not only the SDK's final launch helper.

`scripts/velopack-setup.py` follows the existing checksum-pinned parser vendor
recipe: verify the published crate archive, apply the small tracked diff and
verify the complete generated tree. Only the diff, manifest and setup are
committed; Cargo.lock pins the generated path dependency. No gpui core changes.
A generated tree left from an older diff (vendor/ is not committed, so kept
worktrees keep it) is regenerated from the same pinned archive and diff and
verified before it replaces the old one; `--verify` still only reports it.

The mandatory GitHub Windows agent job exercises `UpdateManager::download_updates`
with a real console-subsystem helper. The test executable starts with
`CREATE_NEW_CONSOLE` and proves its parent window exists, independently of the
runner's pseudoconsole. The actual SDK child's `GetConsoleWindow` must be null.
The synthetic source rejects full downloads,
so fallback cannot mask a patch failure. The helper validates patch arguments
and reconstructs exact fixture bytes through paths with spaces and Unicode.
No installer or installed app is touched.

A same-job negative control removes only `CREATE_NO_WINDOW` from generated SDK
source and requires this actual child-console assertion to fail. The original
generated bytes are restored and verified afterwards. This distinguishes a
hidden process from a test that never reaches the delta command. A real tester
desktop self-update remains separate acceptance evidence.
