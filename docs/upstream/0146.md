# Non-owning focused-input registry

Refs [editing lag](https://git.oklabs.uk/BeFeast/okilum/issues/2803) and
[large edit tools](https://git.oklabs.uk/BeFeast/okilum/issues/2804).
Baseline: `296196975b792998b15eb0161e5c69ba4c5f770b`.

The actual Edit-to-Read ownership diagnostic identified the remaining strong
editor handle in `Root.focused_input`, through `AnyInputState::Editor`.
`Input::render` registers that handle. An input removed while focused cannot
render again to unregister itself. The existing getter rejects stale focus and
clears the slot lazily, preserving lookup correctness while extending the old
editor's lifetime until another lookup, focused input, modal clear or Root release.

The registry now stores a private typed `WeakInputState` for all four input
kinds. The public getter upgrades it only for the duration of a lookup, checks
actual focus exactly as before, and clears matching expired/unfocused metadata.
The registry no longer supplies an editor owner. All actual owners, pending
tasks, parser reuse, source/history/recovery and selection remain unchanged.
Dialog/sheet clearing and focus restoration retain their original order.

This is preferable to an Okilum-only clear on Edit-to-Read: focus metadata is
not an owner in any component, and other normal input removals need the same
lifetime rule. There is no new cleanup task, timer, forced release, core GPUI
change, editor shaping change or public API change.

The existing focus/blur test covers Input, Textarea, Editor and OTP, now also
checking modal focus handoff and restoration for each kind. The existing
removed-focused-input test now removes the actual owning field for all four
kinds, drops only its inspection handle, delivers normal frames/effects and
requires a fired release callback plus expired Weak handle **before** accessing
the getter. That ordering prevents the getter's old lazy clear from disguising
the retention. The unchanged test must fail against the old production registry.

The app regression exercises a real large HTML source, atomic Unicode/CRLF edit,
canonical save, guarded Edit-to-Read and natural editor release, without calling
the focused-input getter or manually clearing the registry. Reopen must create
a new editor/document while retaining exact source, selection and one Undo/Redo.
These tests establish lifecycle and source semantics, not native latency, a leak,
RSS or attribution/removal of the retained aggregate highlighter phase.

Implementation owner is `longbridge/gpui-kit`, pinned at
`928c3eb776a3d733d9b771f7dea27a6a79242ced`. Keep this as an idempotent vendor
diff with the existing stack. A general non-owning registry and these lifecycle
tests are suitable for an upstream proposal after separate authorization; no
upstream issue or PR is submitted here. The consumed private core observer is
not included or repeated. Both reporter issues remain open and the other
save/index, large-tool and long-line/native residuals retain their own scope.
