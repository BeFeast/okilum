# 0103: hanging indent for projected list, task and quote lines

## Problem

Source wrapping keeps a line's leading whitespace as the indent of its
soft-wrapped rows (`WrappingIndent::Same`). Projected (Live Preview) wrapping
did not: every continuation row started at x = 0, under the line's list marker,
task box or quote bar. Quote bars could not repeat on those rows without
covering glyphs.

## Change

- Additive `LineIndent { line, prefix }` and `SourceProjection::line_indents`
  (default empty), with a `line_indent` lookup like `line_hang`. The provider
  names the projected bytes before a line's text.
- `TextWrapper::set_projected` keeps the first row's break, then shapes the rest
  of a wrapped line once more at the width left of the prefix, so every
  continuation row fits under the text. The result records the prefix as the
  line's `indent`, part of the projected wrap cache key. Lines that do not wrap,
  hanging headings, right-to-left lines and gutters wider than half the wrap
  width are wrapped as before.
- `LineItem::wrap_indent` is the one pixel computation for paint and for
  projected caret movement/hit-testing (previously paint only).
- Marker paint repeats a line's quote bars on each continuation row whose
  indent covers them. The old check against the quote scope's end never held
  for per-delimiter scopes, so no bar was drawn on wrapped rows.

GPUI core is unchanged.

## Tests

`hanging_indent_aligns_wrapped_item_rows_under_their_text` (gpui-base) checks
the wrap indent, row widths, a click at the text column, vertical movement from
the item text and the repeated quote bar; the same projection without indents
is the control (rows at x = 0, no bars, movement lands under the marker). The
projected wrap cache test also requires a different indent to miss.
