# Stream the row index for bulk unwrapped source changes (#2804)

`TextWrapper::_update` builds one row item per affected source line even when
soft wrapping is disabled. A whole-file Format can produce hundreds of thousands
of lines; calling `RopeExt::slice_line` separately for each row repeatedly seeks
through Ropey's tree. The previous partial-edit optimization does not avoid this
when every line changes.

For unwrapped changes spanning at least 513 rows, patch 0137 walks the affected
Rope chunks once and counts UTF-8 bytes between LF separators. It emits the same
`LineItem` values and updates the existing SumTree. CR bytes and non-LF Unicode
separators stay in their source line, including across chunk boundaries. The
final row is emitted even when empty. Small edits retain indexed row lookup so
typing in one multi-MB line does not start scanning that line for LF.

Soft-wrapped and projected layout, shaping, source mutation, selection mapping,
Undo/Redo and background Format/Repair computation retain their existing paths.
The change still creates one row item per changed line; it does not make the row
index lazy or claim size-independent whole-file apply.

The regression compares all row lengths, wrap ranges, longest-row selection and
sampled offset mappings after bulk load, an interior replacement and Undo-like
restoration, with CRLF, empty rows, Unicode and a final LF. A counted lookup
control observes the indexed path for a small edit and for wrapped source.
Disabling the streaming branch must fail the bulk-work assertion.

Upstream target: `longbridge/gpui-kit`,
`crates/base/src/input/editor/display_map/text_wrapper.rs`, at the repository's
pinned revision. This is a general optimization for unwrapped source editors;
there is no Okilum-specific hook or GPUI core change. The patch is kept separate
and applied/verified by `scripts/vendor-setup.sh`. Upstream submission remains a
separate action; no issue or PR has been opened upstream.
