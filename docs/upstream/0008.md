# Search rendered TextView text without modifying Markdown or HTML

Tessera's find and search jump previously inserted inline-code delimiters into
Markdown source. Searching a code fence displayed those literal delimiters;
inline code was broken, and HTML had no visible highlights.

Add retained search ranges over parsed visible UTF-8 bytes. Search backgrounds
compose with existing syntax, inline-code fonts, links and marks. One current
match is stronger than the other matches. Search does not reparse source or
change the reader input or copy format. Enter navigation wraps and reveals the containing block,
then the actual glyph line and any horizontally scrolled table column.

Custom renderers declare named plain-text, Markdown or HTML parts in render
order and render those same parsed documents with `MarkdownNode::render_part`.
The shared nodes preserve one search/selection owner, include offscreen and
recursive content, and retain each part's local reference links. Whole-document
source copy remains the original TextView input (Tessera core may already have
rewritten Obsidian constructs; canonical raw-source clipboard is a separate issue); partial selection uses the selected
part's own source. Tessera uses parts for callout labels/bodies, embeds,
highlighted paragraphs and local-image captions.

The patch builds on 0006; the vendor script verifies the cumulative result in a
disposable index because a later patch may refine an earlier patch's lines.
No gpui core changes.

Validation: targeted gpui-base tests cover rich Markdown, decoded HTML,
Unicode byte boundaries, unchanged plain/source copy, current-match wrap,
async replacement/append, and recursive custom parts with selection clearing.
Native evidence and final review are recorded in the Tessera reader-find issue.
