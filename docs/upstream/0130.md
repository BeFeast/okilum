# 0130: external editor search presentation

An application may put Find in its document header. Calling `set_search_query`
already computes matches, and the public next/previous methods already step
through them, but the editor only painted those matches with its own search
session open. Opening that session also mounted the toolkit search strip.

Add `set_external_search_presentation(bool)` to `InputBaseState`. In external
presentation, matches paint without mounting or focusing the toolkit strip.
The host retains query, count, stepping and focus ownership. Closing search
ends either presentation and preserves the existing exact match-return anchor.
The default remains the internal search strip; source bytes, caret and Undo
are unaffected by changing presentation.

An LSP completion or hover may still mount the shared overlay host. In external
presentation its search panel must not call `hide_with_focus`: that helper closes
the underlying search session as well as changing focus. The host leaves search
lifecycle and focus with the application's Find field instead.

The patch follows the complete stack through 0129 on pin `928c3eb7`. It changes
three toolkit files: the session API, match painting and strip mounting. GPUI
core is unchanged. The host adapter unfolds a returned hit using the existing
public `unfold_at` API.

Reproduction and acceptance belong to Okilum's native editor adapter tests:
set a query with external presentation enabled, verify painted match paths
and absent toolkit search strip, step forward/back to a folded hit, then clear
and verify marks disappear without changing source bytes. Those tests must
also run against a disabled-paint negative control and retain external focus when
an LSP overlay updates. Native execution is pending while this patch is prepared
alongside the shared header work.
