# input: preserve CRLF cursor boundaries and document navigation

Patch `0007-input-crlf-cursor-boundaries.diff` targets gpui-kit
`928c3eb776a3d733d9b771f7dea27a6a79242ced`. No gpui core changes.

The native Tessera #104 report typed inside an existing CRLF pair. Two independent
baseline reproductions identify the input layer: End moves between CR and LF in
`\u{feff}first\r\nlast\r\n`; Linux Ctrl+End has no binding and leaves the cursor
where it was. An LF End positive control moves correctly. The original linux-test-host
controller did send Ctrl+End; its exact fallback path is not inferred from this
unit reproduction.

Add the standard non-macOS Ctrl+Home/End and selection bindings. Clip cursor and
selection movements outside CRLF pairs, and make Left/Right cross the pair in one
step. A standalone CR remains an ordinary character. The rope, source text,
byte/UTF-16 conversion and explicit range replacement remain unchanged, retaining
BOM and mixed line endings exactly. This is cursor positioning, not normalization.

Upstream regression `textarea_cursor_treats_crlf_as_one_newline` covers End,
Left/Right, selection, document start/end, a leading CRLF and a lone CR. Tessera's
native key-dispatch test adds platform document shortcuts and exact source-write
payload assertions; existing source/conflict tests retain the persistence contract.

This patch is intended for submission to `longbridge/gpui-kit`; upstream publication
is tracked with Tessera issue #104. A submitted/merged upstream PR is separate from
local test or native acceptance evidence.
