# Suppress managed tooltips while a deferred popup is open

Pending upstream submission. Reproduced by Windows Reader QA: a Find in note
tooltip painted above the open More menu and obscured its first item.

TooltipOverlay yields to the existing deferred-popup interaction context.
It clears visible and pending tooltips during render, rejects new requests
while the popup is open, and checks the context again when a hover timer fires.
After dismissal, ordinary tooltip requests work again. No GPUI core changes.

The downstream Reader CI test opens the actual More button, proves a tooltip
can render before opening, checks visible/new/delayed suppression, and proves
tooltips recover after Escape. The patch adds 14 lines and removes 2.
