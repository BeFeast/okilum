# Avoid the intermediate full-row String before shared shaping input

Related unfinished [editing lag](https://git.oklabs.uk/BeFeast/okilum/issues/2803)
and [large edit tools](https://git.oklabs.uk/BeFeast/okilum/issues/2804).
Baseline: `a7a7db120e4b08c546cb02af45c9214801e2a0fb`.

`TextElement::layout_lines` first materializes each visible Rope row as a
contiguous String. It then constructs each shaped subrange with
`line_text[range].to_string().into()`. For the single complete unwrapped range,
that intermediate String duplicates bytes that are already contiguous.

The locked GPUI shared-string crate is **gpui-pre-shared-string 0.3.3**, backed
by **smol_str 0.3.6**. SharedString::from(String) delegates to SmolStr::from(String),
which calls SmolStr::new. Its heap representation allocates an Arc from the
borrowed string bytes; it does not adopt the String's allocation. Merely moving
the String variable would therefore not make this conversion allocation-free.
See [SharedString constructor](https://docs.rs/gpui-pre-shared-string/0.3.3/src/gpui_shared_string/gpui_shared_string.rs.html)
and [SmolStr constructors](https://docs.rs/smol_str/0.3.6/src/smol_str/lib.rs.html).

Patch 0143 passes the existing row's borrowed str directly to SharedString only
when soft wrap is disabled, the row has exactly one visual range, and that
range is exactly `0..row.len()`. The row String remains available for the later
indentation/length reads. SharedString owns its copied shared storage before
the borrow ends. There is no transferred lifetime, slicing of shared storage,
new threshold, or change to the wrapping/shaping representation.

For a long full row, the conversion stage goes from two source-sized
allocations/copies (temporary String, then shared storage) to one (shared
storage). The earlier Rope-to-String materialization remains, as do all later
shaping/cache/glyph copies. Wrapped and nonzero/subrange construction keep the
original expression. Small full rows receive the identical bytes through the
same SmolStr constructor; inline storage may avoid a heap allocation, without
changing their layout or behavior.

No text, run, font, color, background, bidi, wrap, geometry, caret, selection or
hit-testing input changes. Native word boundaries, full native geometry
assertions, ASCII admission, fallback/reshape limits and cache caps are untouched.
No source/history/save/conflict/recovery, highlighter task or parser behavior
changes. This paint-stage correction is outside update_highlighter and cannot
be credited with removing its retained 64–67 ms aggregate.

## Controls

The gpui-base test binary installs a System-delegating allocator that observes
only a thread-local scope inside the **production row conversion helper**.
Scope collection allocates after observation is disabled. It counts actual
allocations at least as large as the shaped range; it does not trust a counter
next to the optimized branch. No allocator/instrumentation is included in
production or in dependent application test binaries.

- A multi-MB UTF-8 full-row conversion must allocate shared storage once. A
  deliberately retained old full-copy expression must fire two allocations
  using the same meter, proving both the meter and constructor-copy contract.
- A real GPUI Editor frame with a multi-MB unwrapped row must reach layout_lines
  and the scoped conversion (nonempty observations), allocate once there, and
  install geometry carrying the exact source bytes. A retained source-layout
  cache is cleared before that frame so a cache hit cannot satisfy the test.
- Full, wrapped, nonzero UTF-8, combining/RTL/emoji and small ranges retain exact
  original bytes. GPUI test-context shaping compares the same styled inputs,
  complete glyph indices/IDs/positions, width, caret coordinates and hit-testing
  with the old String construction. Long wrapped/nonzero controls must still
  observe the two-allocation original path. These are headless GPUI controls,
  not native platform geometry or key-to-paint certification.
- The compiled negative restores the actual old subrange-to-String expression
  in the helper while retaining the same actual-path allocation scopes. Both
  full-row regressions must fail at their unchanged allocation assertions;
  compile errors or an unfired scope are not a passing negative. Source hashes
  and the cumulative vendor stack must verify after restoration.

No timing sweep, native fallback retest, device experiment, RSS or 16 ms claim
is needed or made. Whole-file Apply/Undo Tree::edit traversal/COW attribution
is still missing evidence; pending-coordinate representation and running/retired
Tree ownership constraints remain. Long-line source materialization, comparison,
glyph copying and genuine unbreakable-context native fallback remain separate
residual work. Both original reporter issues remain open.

## Upstream

The owner is longbridge/gpui-kit, `crates/base/src/input/base/element.rs`, not
GPUI core or the native shaper. Avoiding an unnecessary temporary String before
constructing immutable shared text is general and upstreamable with these
range/UTF-8/allocation controls. Carry one cumulative vendor patch at the pinned
revision; an upstream submission requires separate authorization and is not
opened here.
