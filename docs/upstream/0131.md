# 0131: worker-prepared external Find ranges

The header Find host matches a revision-bound Rope snapshot on a debounced
worker. The existing `set_search_query` API compiles and scans synchronously;
using it in a source-mutation subscription would put whole-document work on the
editing keystroke path.

Add `set_external_search_results(query, case_insensitive, ranges, current, cx)`.
The caller verifies source revision before installing byte ranges. Installation
clones only the Rope handle, replaces shared ranges/current index and enables
external painting with the toolkit strip closed. It does not build a matcher,
flatten source text, move the caret or edit source. Its matcher has no local
regex: later input mutations cannot silently rescan an external query. Normal
internal Find still uses its existing matcher. The host explicitly unfolds and
selects a hit and closes search before retiring results to preserve the existing
match-return anchor.

The patch follows 0130 on pin `928c3eb7`, touches only the editor search API and
leaves GPUI core unchanged. Application regression tests cover actual matches,
case/stepping, folded hits, source-mutation debounce, clearing without source
edits and cached-header/SidePanel isolation. The issue-local idunn compiled
controls restore synchronous matching, suppress mutation refresh, and independently
remove stamp/generation guards while a real worker is held. These controls are
retained with PR evidence; they are not run by the routine CI suites. CI runs the
positive application regressions and the existing data-view native controls.
