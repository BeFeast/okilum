# 0106: expose first/last visual-row caret queries

Terminal-style prompt recall must not take ArrowUp or ArrowDown away from a
wrapped multiline draft. Counting newline characters treats all soft-wrapped
rows as one line; using the raw byte offset at a wrap boundary also loses
whether the caret is painted at the end of one row or the start of the next.

`InputBaseState::is_caret_on_visual_edge(end)` reads the same display/wrap map
and line-end affinity as native vertical movement. It returns false for a
selection, active IME, pending vertical move, or a source/presentation/width
that no longer matches the painted layout. Width compares the painted text box,
not the padded outer input box. Empty input is on both edges, matching T3's
DOM editor even before its first text layout. The caller can then leave the key
to the input's ordinary movement handler. It requires no text clone or layout
rebuild. The patch changes gpui-kit base only, never gpui core.

The regression `textarea_visual_edges_follow_wrap_resize_affinity_and_selection`
uses actual textarea layout. Its positive controls require a narrow window to
wrap and a wide resize to remove that wrap. It distinguishes both affinities
at the same soft-wrap byte offset, selection/IME, a stale edit and hard-newline
bottom geometry. The targeted vendor test and the project suite pass on Linux.
This API is not submitted upstream yet; it builds on the existing
source/presentation identity and wrap-affinity patches.

The local adapter depends on prior source/presentation and wrap-affinity patches.
Upstream publication follows the deliberate attributed submission process in
[README.md](README.md); this document is the ready-to-paste proposal, not a claim
that the standalone diff applies to the pinned upstream without its dependencies.
