# 0100: theme-independent syntax spans

`SyntaxHighlighter::semantic_spans` exposes the ordered semantic captures of the
existing parsed tree, clipped to current UTF-8 text. `styles` resolves those same
spans through its theme, retaining its existing overlap composition.

Okilum uses this additive API to prepare code captures on the Live Preview
background worker. Projection shaping receives those captures with the current
Reader syntax theme and Settings code font; it does not parse on the UI thread.
Captures from a different source revision are not reused. The existing input,
node and presentation-style caps remain in force.

The patch changes only gpui-component's highlighter, not gpui core. It is suitable
for upstream: applications that shape projected text can reuse the component's
matching, injections and UTF-8 clipping without maintaining another highlighter.

Validation is pending the bounded CT141 pass for #1991. Application regressions
compare Reader and Live colors for C# aliases and popular languages, exercise
both syntax themes, and reject stale offsets. The public getter also has a
UTF-8 clipping positive control through those regressions.
