# Check grouped source-edit boundaries on the Rope (#2804)

`InputBaseState::replace_source_edits` previously flattened the complete source
before checking a group's byte ranges and again after applying the group to
clip its final selection. Repair may change only three keys in a multi-MB file;
those two String allocations and copies were still proportional to the complete
source, on the foreground thread.

Patch 0138 checks the same UTF-8 boundaries through the existing Rope and uses
its existing left-biased `clip_offset` for the final selection. It explicitly
rejects a range beyond EOF before querying Rope boundaries. Range ordering,
preflight-before-mutation, grouped Undo, native replacement and selection
semantics retain their existing paths. This removes two complete-source
conversions; it does not make whole-file row-index construction asynchronous or
claim that Format/Undo satisfies a frame budget.

The app regression uses the existing foreground allocation meter around real
native grouped-edit calls. It covers rejected groups (including an invalid
second UTF-8 range), accepted edits at the beginning/middle/end of a multi-MB
file, selection clipping inside an inserted emoji and exact one-step Undo/Redo.
An explicit whole-source conversion must fire the same meter. Restoring the
previous implementation must fail the allocation bound.

Upstream target: `longbridge/gpui-kit`,
`crates/base/src/input/base/state.rs`, at the repository's pinned revision.
The grouped-source-edit API was introduced by local patch 0087, so submission
depends on upstreaming that API first. This is a gpui-kit change and does not
patch GPUI core. The diff is applied and verified by `scripts/vendor-setup.sh`.
No upstream issue or PR has been opened.
