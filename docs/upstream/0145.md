and [large edit tools](https://git.oklabs.uk/BeFeast/okilum/issues/2804).

Owner: `longbridge/gpui-kit`, pinned at
`928c3eb776a3d733d9b771f7dea27a6a79242ced`, patches through 0144.
The app lock resolves tree-sitter 0.26.13, GPUI/scheduler 0.3.3 and

## Actual release boundary

The app language menu calls `Reader::select_code_language`. It changes the
revision-bound edit-tool language override, not the native syntax adapter.
This patch does not claim a native language-menu replacement defect.

A clean external reload does replace that adapter:
`Reader::refresh_source_in_background` → `Editing::replace_clean_source` →
`replace_clean_source` → `EditorState::set_value` → `reset_highlighter`.
The editor entity remains alive. The adapter releases its highlighter Rc;
if a parse continuation still owns another Rc, cancellation schedules its
eventual foreground-future destruction instead. The final Rc release destroys
the current published syntax fields on foreground in either case.

These fields are separate from necessary parser reuse snapshots, detached
replaced-syntax batches (0141) and abandoned completed outputs (0144). Moving
those owners does not move the published payload's final release. Query caches
for injection languages are local to layer construction; the current layers
can be the last owners of those compiled queries too.

The baseline deterministic app control uses a real 421,212-byte HTML source,
Hebrew, emoji, combining marks, CRLF, 24 JS scripts and CSS. After a real edit
and canonical autosave, it registers borrowed addresses of actual current
Trees, unique Queries and Parser. It adds no Tree/Rc owners. A real disk change
and production background reload release the old highlighter while preserving
the editor entity. All 26 marked Trees and 4 unique Queries are destroyed and
42,744 actual subtrees freed on the UI refresh/effect path. The Parser is also
deleted there; its internal subtree-free count in this fixture is zero.

These are ownership/work counts, not durations, RSS, natural occurrence rates
or native key-to-paint evidence. They neither isolate nor remove the retained
64–67 ms aggregate highlighter phase or foreground `Tree::edit` traversal.

## Bounded ownership transfer

The native adapter binds its existing background executor when it updates the
highlighter. Only on final `SyntaxHighlighter::drop`, its already-owned Query,
injection Query, Tree and injection layers move into one detached cleanup task.
There are no new Tree/source clones. Relative syntax-field destruction order is
preserved. Standalone highlighters without an executor keep their original
destruction behavior.

Active/pending coordinates, style/fold queries, parser reuse, source admission,
language binding and publication ordering are unchanged: the transfer occurs
after the highlighter's final owner has gone. Parser, source Rope, metadata,
UI entities/Rc and history stay with their original owners. The cleanup task
cannot publish or mutate any replacement editor state. It is detached from
parse cancellation. Its finite existing payload can remain alive until the
executor schedules cleanup; this is not a new aggregate memory bound or a
guarantee about cleanup after the executor stops.

## Focused controls

Two checked-in native adapter controls use the real `EditorState::set_value`
boundary, once after publication and once with a real debounced parse
continuation retaining the old highlighter. They require at least 24 actual
injection layers, zero layer destruction at foreground release, completed
background destruction of every old layer, and replacement source/folds matching
a fresh parse. A deliberate local highlighter destruction fires the same real
layer-destructor meter as a positive control.

The private app-lock C-counter regression also requires destruction of all
marked Trees, unique Queries and Parser after drain. Its owner-field scope
covers natural field destruction after the Rust Drop body, not just that body.
It distinguishes background final retirement from other parser, replaced and
abandoned-output cleanup scopes. The same actual app reload verifies exact
source/UTF-8/CRLF, fresh syntax, unchanged editor identity, stale menu rejection,
the new clean disk base and one atomic edit/Undo against that base. Clean reload
intentionally clears the prior base's Undo history.

The compiled old-production negative restores the exact baseline highlighter
and adapter, applies identical observers and retains the same assertions. It
must fail after actual complete destruction because candidate Trees/Queries
were destroyed under UI owner fields; a compile failure or unfired release is
not a valid negative control. Only focused registrations are enabled in the
app harness to fit its compilation memory budget; that is not a full suite
verdict. All instrumentation, lock/manifest changes and registration exclusions
must be restored and verified after validation.

## Upstream plan and remaining scope

This final syntax-owner cleanup belongs in `longbridge/gpui-kit`; it can be
proposed with the lifecycle controls after separate upstream authorization.
No upstream issue or PR is opened here.

Edit-to-Read did not establish final editor release: a control still observed
one strong Entity owner after normal frame callbacks. Its owner is unresolved;
no forced release or acceptance claim substitutes for that missing evidence.
Parser/source/history destruction, necessary running/retired sharing, wide
Tree traversal, XML/other long-line paths, platforms and native latency remain
separate unfinished parts of the original reporter issues. Existing functional
large-tools/Cancel/stale/one Undo/post-Repair/menu/durability and delivery proofs
keep their original scope and are not repeated by this lifetime-only slice.
Both reporter issues remain open; Mac/Windows are not verified here.
