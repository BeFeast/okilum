# Preserve window text selection through cached GPUI paint

A cached selectable Markdown subtree can re-notify its owner on every unrelated
frame. `finish_frame` sees no fresh registration from cached paint, removes the
participant, and clears an already-empty selection. The text adapter forwards
`SelectionChanged(None)` to the cached view, causing another render. A virtualized
chat feed then redraws while its independent composer is being edited.

Tie each painted registration to an entity held only by GPUI element state. That
state is retained by cached paint and dropped on actual unmount, even if the
application keeps its participant handle alive. The sweep preserves registrations
with a live paint lease; direct/manual registrations retain the existing frame
expiration rule. Empty clearing resets its copy cache without emitting selection
changes or invoking an adapter clear callback. Actual geometry and local selections
still clear once.

This patch changes `gpui-base` only; it does not patch GPUI core or retain stale
participants permanently. It is carried as `0095-cached-text-selection-registration.diff`
in Okilum's cumulative vendor stack for #1787, and has not been submitted upstream.

Regressions cover cached paint preserving selected Copy text, unmount clearing a
still-live participant, and an empty clear producing no notification while a real
local clear supplies a positive control. Existing copy/selection and stale-cleanup
tests remain required. Okilum also exercises selectable Markdown plus real composer
input with zero feed notifications, renders and row layouts.
