# Stream bulk source rows into the display tree (#2804)

Patch 0137 scans an unwrapped bulk edit's Rope chunks instead of seeking each
row. It still stages every LineItem in a contiguous Vec before constructing
its SumTree. Format can create hundreds of thousands of rows, so this buffer
scales with the complete row count on the foreground thread.

Patch 0139 feeds those rows directly into SumTree::from_iter. The existing
tree implementation packs iterator items into leaves without collecting all
items first. Its smaller node vectors remain. The small/wrapped row path,
512-row-span threshold, tree splice and source byte geometry remain the same.
Chunk boundaries can bisect lines; only LF ends a row, CR is retained, and a
final row is always emitted, including after a trailing LF.

The native allocation regression replaces 160k rows with 180k rows in a plain
text editor, checks exact one-step Undo/Redo and bounds the largest allocation
below 2 MiB. Both source strings are below 1 MiB; the former row buffer is
several MiB. An explicit 4 MiB allocation must fire the meter, and restoring
the previous production path must fail the regression. The retained vendor
geometry test also covers a sparse bulk span containing a giant line and
replacement boundaries at nonzero UTF-8 columns.

This change removes the intermediate row-item buffer. It does not move row
indexing or highlighting off the foreground thread, establish native input
latency, or claim a frame budget. Same-host measurements and negative-control
results must accompany the PR before any performance conclusion.
