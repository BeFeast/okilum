# 0104: a double-click on a rendered block selects its source

Patch 0063 lets a press on a rendered projection block (a table, an image) reveal
it, with the caret where the block's element says the press landed. A
double-click then reached the revealed source as an ordinary second click and
selected one word of it, under a pointer that had pointed at rendered pixels a
moment before.

With this patch the editor remembers the source range of the block the first
press revealed, for that source revision. The second press of the double-click,
anywhere in that range, selects the block's whole source instead of a word,
with the caret at the block's start so the view does not jump to its end. When
both presses arrive before a repaint (the block is still painted), the second
press selects it from the painted block directly. Any other press clears the
remembered range; a double-click on ordinary text still selects a word.

Okilum uses it for Live Preview (#1642): a double-click on a rendered table,
image or callout opens its source with the content selected.

The patch changes only `gpui-base`'s input state, not gpui core. Test:
`double_click_on_a_rendered_block_selects_its_whole_source` covers both
orders (repaint between the presses, and none) and keeps a word double-click on
plain text as a positive control. Not submitted upstream yet; it builds on 0063,
which is not upstream either.
