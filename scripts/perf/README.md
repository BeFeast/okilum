# Scroll probe (#1290 Windows, #1004 Intel Mac)

Answers two questions about scrolling a large note: **how fast** (frames per second, the same
notes on the same host before and after a change) and **where the frame time goes** (view
render, layout, text shaping, paint, present). Measurement only: the product code is not
touched, and the gpui sources stay unpatched (see AGENTS.md).

## Rules that keep the numbers worth something

- **One machine, one session.** Only runs from the same host compare; a before and an after
  come from the same VM or Mac in the same sitting. WARP (VM 150) and a real GPU (VM 151) are
  different hosts.
- **The same notes.** `scroll/gen-notes.py` writes `big-24k.md` (the #1290 note, byte for byte
  as `scripts/windows/qa-vm/scroll-frametime.ps1` writes it) and `Long-10k.md` / `Long-LP-700.md`
  (the notes of #1004's Hedva vault, regenerated by a port of that vault's generator).
  `scroll/manifest.json` pins their SHA-256; the probe
  refuses a note that does not match, and `test_perf.py` fails if the generator drifts.
- **A quiet host.** Windows: the probe waits for the guest's CPU to settle (Defender and the
  indexer run after a boot) and records whether it did (`quiet=` in `summary.txt`). The VM
  shares the CPU of its host: no cargo build on CT141 and no other guest running during a run.
  Mac (Hedva): the QA lock, `nice -n 10`, and the audio rig left alone.
- **A host that can pace frames.** gpui draws once per `DwmFlush()` (its VSyncProvider thread),
  so a host whose `DwmFlush` takes 80 ms caps every app at 12.5 fps whatever the note: VM 151
  measured exactly that with Okilum closed, and a 20-line note scrolled at the same 12.5 fps
  (#1290). `scroll/windows/dwm-flush.ps1` times it; `scroll-trace.ps1` runs it first and every
  rep says `host_capped=True` when the median is above 20 ms. Read frame *cost* (draw, present)
  from the trace on such a host, never the frame rate.
- **Input must not be the limit.** The wheel helper sends `-WheelHz` notches a second (default 60,
  against absolute deadlines) and records what it really sent as `wheel_hz`; a frame rate at or near
  the input rate says nothing about the app. (The first probe's `Start-Sleep 16` loop sent 35-40 a
  second: harmless while the host paced at 12.5 fps, a cap of 38 fps once it paced at 60 Hz.)
- **Positive controls in every rep.** The before and after screenshots must differ (the note
  really scrolled, otherwise `valid=False`); the trace must hold redrawn frames inside the
  wheel burst (the analyzer says so when it does not); an idle window shows no redraws.
- **Tracing must not be the thing measured.** Run the trace build once with the trace off
  (`OKILUM_FRAME_TRACE` unset) and compare its external frame rate with the installed build's.

## Parts

| part | what |
|---|---|
| `frame-trace/patch.py` | patches throwaway copies of `gpui-pre` (and `gpui-pre-windows`, `gpui-pre-apple`) so each presented frame writes one line: gap, draw, request_layout, compute_layout, prepaint, paint, present, time in the line-layout cache, time and count of text shaping, scene sizes; Windows adds the Present split, macOS the `next_drawable` / encode / commit split. Field list in its docstring. |
| `build-windows-trace.sh` | cross-builds a Windows `okilum.exe` with that trace (same profile as shipped; `--no-debug-assertions` for the comparison) |
| `build-linux-trace.sh` | builds a Linux release `okilum` with that trace (CI guard, Linux runs) |
| `scroll/linux/scroll-trace.py` | the Linux probe under X11 (Xvfb): 120 wheel notches every 16 ms, a window-pixel check that the note scrolled |
| `scroll/budget.py` | the CI guard: the frame must not grow with the note (see below) |
| `scroll/windows/scroll-trace.ps1` | the Windows probe: wheel every 16 ms for 10 s, DXGI `Present_Start` intervals from ETW as ground truth, the trace as the breakdown |
| `scroll/mac/scroll-trace.py`, `wheel.swift` | the Mac probe (Hedva): 120 pixel wheel events of 40 px every 16 ms, no screen capture while measuring |
| `scroll/analyze.py` | one table row per run: fps, interval p50/p95, medians of every phase |

## Windows (VM 151 `okilum-win-gpu`, sindri)

1. On CT141 (no other build running): `scripts/perf/build-windows-trace.sh OUT` and
   `scripts/perf/build-windows-trace.sh OUT-noda --no-debug-assertions`.
2. Roll VM 151 back to `clean` (guarded, as in `scripts/windows/qa-vm/`), copy `OUT/` (the exe
   and its `gpui-shaders/`), the notes, `manifest.json`, `scroll-trace.ps1`, `run-gui.ps1` and
   `gpu-probe.ps1` to `C:\qa\`.
3. `powershell -File C:\qa\scroll-trace.ps1 -Note C:\qa\notes\big-24k.md -Label shipped -Exe C:\qa\trace\okilum.exe -Trace`
   (`-Label control` without `-Trace` for the tracing-off check; no `-Exe` runs the installed build).
4. Copy `C:\qa\bench\scroll\<label>` back and run `scroll/analyze.py <label>`.

### A Windows VM with a GPU and no monitor: give it a virtual one first

VM 151 (`okilum-win-gpu`, Iris Xe passed through, nothing plugged into it) has no monitor with an
EDID for Windows, DWM's timing query fails, and `DwmFlush()` returns every 79 ms: every gpui app
runs at 12.5 fps, whatever it draws (#1290). `scroll/windows/idd-install.ps1` adds an Indirect
Display (IddCx) monitor, 1920x1080 at 60 Hz, rendered on the Iris Xe, and `DwmFlush` goes to 16.6 ms.

- Driver: VirtualDrivers/Virtual-Display-Driver release 25.5.2, asset `Signed-Driver-v24.12.24-x64.zip`
  (SHA-256 `f93e7ce3d640c83c419b1b72d2c83b2d8e34d83e8b7ba11f3328a40d2da82fa4`; files `MttVDD.dll`,
  `MttVDD.inf`, `mttvdd.cat`, `vdd_settings.xml`; signed by SignPath Foundation via GlobalSign).
  Copy them to `C:\qa\idd\`, then `powershell -ExecutionPolicy Bypass -File C:\qa\idd-install.ps1`
  (`-CheckOnly` first: it only verifies the signatures).
- The script adds the SignPath signer certificate to the guest's `TrustedPublisher` store (without it
  Windows refuses the package with 0xE0000242), writes `C:\VirtualDisplayDriver\vdd_settings.xml`,
  and creates the root device the way `devcon install` does. It changes the guest's trust store:
  take a snapshot first. Run the script once; a second run adds a second monitor.
- Check with `dwm-flush.ps1`: p50 should be about 16.7 ms (and `host_capped=False` in the probe).
- VM 151 snapshots: `clean` (no display, `DwmFlush` 79 ms: do not use for speed), `pre-idd`,
  and **`idd`** (clean + this display): start speed checks from `idd`.

## Mac (Hedva)

Take `/tmp/okilum-hedva-qa.lock` first (shlock), then `scripts/perf/build-mac-trace.sh ~/qa1290`
(nice 10, patches `gpui-pre` and `gpui-pre-apple`, compiles `wheel.swift`), then
`python3 scroll-trace.py BINARY OUT VAULT reader:Long-10k.md …` and `analyze.py OUT/<scenario>`.
The headless Mac has a virtual display at 30 Hz: the `drawable` column shows whether
`next_drawable` is what waits, which is the question to repeat on a Mac with a real display.

The default stream is 60 notches a second, which a 7.5 fps display turns into ~8 notches (~320 px)
per frame. `WHEEL_EVENTS=120 WHEEL_INTERVAL_MS=130` sends one notch per frame instead, the distance
per frame of the default stream on a 60 Hz display; run both on the same build, interleaved. The
`entry frames %` column is the share of redrawn frames in which the text shaper ran (new text came
into view).

## Linux and the CI guard

`perf-linux` (hosted, on every PR that touches app code, required by `ci / check`) builds the
trace binary, scrolls `big-head-320.md` and `big-24k.md` (the first 320 lines of the 24k note:
the same blocks on screen, only the length differs) under Xvfb and runs `scroll/budget.py`. It
fails when `request_layout` p50 grows by more than 1 ms with the length, `draw` p50 by more than
3 ms, or `draw` p95 on the 24k note exceeds 30 ms; a rep that did not scroll fails as
"no evidence". The growth checks compare two notes in one run on one machine, so the runner's
speed cancels out; `present` is left out because under Xvfb it is the software rasteriser.
A #1294-style regression (work per frame over all of a note's links) fails it: on CT141
`request_layout` grew +3.0 to +4.1 ms with #1294 reverted, +0.1 ms on main.

By hand on CT141 (through its build wrapper in `~/bin`, which holds the one-cargo lock):
`scripts/perf/build-linux-trace.sh OUT`, `scroll/gen-notes.py NOTES --check`, then
`DISPLAY=:N python3 scroll/linux/scroll-trace.py OUT/okilum RUN NOTES reader:big-head-320.md reader:big-24k.md`
and `scroll/budget.py RUN/reader-big-head-320 RUN/reader-big-24k`.

## Reading a row

`interval` is the wall-clock time between redraws; `draw` is the part spent building the frame;
`interval - draw` is time not spent drawing (a blocked Present, or waiting for the next frame to
be due). `cache` is the time in the line-layout cache (lookups and misses), `shape` the part of
it spent in the platform text shaper on misses: `cache - shape` is lookup cost.
