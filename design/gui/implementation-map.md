## Implementation sequence

1. Build the reference-driven three-pane shell: neutral navigation, persistent goal/source master list and selected detail; place search/New thought in the global toolbar. Keep retained `Workspace`/`BrainView` entities and selection routing. Apply GUI-owned neutral surface/blue action aliases over immutable brand imports; retain Noto Sans/Cascadia Code and existing rendering/performance boundaries.
2. Extract master-list rows, detail headings and restrained sections for attention, goal header, next action, criteria and historical stages without changing runner state semantics. Keep Prototype tools secondary and out of the production hierarchy. Use stable entity identity to avoid focus/scroll churn during polls.
3. Connect source-return navigation and explicit dirty navigation dialog to existing draft protections. Add readable manual conflict comparison; retain byte-preserving source reconstruction rather than serializing rendered Markdown.
4. Reorganize connector and export presentation around the existing guarded APIs. Do not add token storage, provider probes on page load or implicit execution.
5. Verify keyboard/density/theme/laptop behavior and native accessibility support separately. Preserve existing renderer/search gates; replacing the application with the HTML prototype is outside scope.

## Known gaps and pitfalls

- The alpha scope document's final baseline paragraph describes the pre-integration single-goal shell. Current additive workspace/multiple-goal implementation is visible in the linked files and application API's alpha section; do not reimplement ownership based on that historical baseline.
- `next_action` currently checks interrupted/failed discussion, while the documented chat terminal error is `error`. Native presentation should cover the documented error as well as interrupted status; this is a code-read observation, not a tested production defect.
- Preview is a bounded rendered projection (8 MiB text, 8 MiB per local image, 32 MiB unique image bytes per reply). Unified large-workspace search and incremental remote preview indexing need their own design/performance work. The prototype's search is a fixture filter.
- Automatic merge and desktop-crash draft recovery are deferred. Historical conflicts are inspectable through the API, but a reopened conflict-history list is not an alpha GUI guarantee.
- Changing account/project routing is restricted even after completed external history. Settings success is not proof of provider execution; unreachable auth is not an empty inbox.
- An existing T3 web URL can identify a submitted attempt before turn correlation succeeds. A result without a checkpoint cannot claim file/diff verification. A later checkpoint does not silently rewrite the first immutable receipt.
- Do not advertise Cancel unless adapter capabilities support it. Reconnection reconciles already-started work and does not start a prepared stage.
- Export is saved knowledge, not recovery of execution journals, credential references or unsaved drafts. An extracted archive cannot authorize replay.
- The native GPUI accessibility tree remains a separate acceptance concern. Browser keyboard checks cannot close that gate.

## Evidence receipt expectations

Existing regression names in `brain.rs` provide relevant starting points: `goal_switch_restores_own_selection_and_blocks_dirty_source_navigation`, `failed_selection_and_delayed_drafts_never_change_visible_goal_ownership`, `completed_goal_replaces_confirmation_but_keeps_saved_result_access`, `native_conflict_keeps_draft_and_inspects_newer_versions_without_discard`, and `lost_resolution_ack_reuses_only_the_exact_displayed_revision_request`. `export.rs` covers corrupted transport and valid no-dispatch download. They were read here, not rerun as part of this documentation slice.

For a native change, record commit/build identity, exact fixture manifest, before/after source hashes, goal/stage/task/thread/result identity in evidence details, screenshots at 1280×800 and laptop size, keyboard traversal, and error recovery. Prove absence claims with a positive control (for example, dispatch counter increments on intentional Start and stays unchanged on reconnect). Keep timing comparisons on one machine/session.

Prototype evidence must be labeled synthetic and record browser/viewport/theme/density, the exercised action and observed result. Token contrast checks establish only the named color pairs, not a full screenshot or native accessibility audit. The [handoff](archive/handoff.md) owns the current token provenance and final verification receipt. Neither historical native screenshots nor a successful prototype run constitutes user acceptance of a functional product change.
